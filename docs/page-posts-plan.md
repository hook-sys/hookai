# Page Posts ফিচার — বিস্তারিত পরিকল্পনা

Hook-এ রেগুলার (organic) Facebook Page পোস্টের ফিচার যোগ করার পরিকল্পনা।
ব্যবহারকারী Hook থেকেই পেজ বেছে নিয়ে ক্যাপশন লিখে ছবি/ভিডিওসহ পোস্ট পাবলিশ করতে পারবে —
আলাদা করে Facebook-এ লগইন করা লাগবে না, Hook-এর বিদ্যমান Meta সংযোগ দিয়েই কাজ হবে।

তারিখ: 2026-11-03 · অবস্থা: সিদ্ধান্তগুলো চূড়ান্ত (অনুচ্ছেদ ১০), কোডিং শুরুর অনুমতির অপেক্ষায় · কোনো কোড এখনো বদলানো হয়নি

## ১. লক্ষ্য ও পরিসর

### MVP-তে যা থাকবে (Mason-এর সিদ্ধান্ত অনুযায়ী, 2026-11-03)
- Facebook Page-এর তালিকা থেকে পেজ বেছে নিয়ে পোস্ট তৈরি
- পোস্টের ধরন: শুধু লেখা, একটা ছবি + ক্যাপশন, একটা ভিডিও + ক্যাপশন
- মিডিয়ার উৎস দুইটাই: সরাসরি আপলোড **এবং** Google Drive লিংক
- সব পোস্ট প্রথমে **ড্রাফট** হিসেবে থাকবে; Mason **approve** করলেই কেবল পাবলিশ/শিডিউল কার্যকর হবে
- **Hook-এর নিজের শিডিউল:** approve করা পোস্টে সময় বসালে Hook-এর cron ওই সময়ে পাবলিশ করবে
- পোস্টের তালিকা: ড্রাফট/অনুমোদিত/শিডিউল করা/পাবলিশ হয়েছে (permalink সহ)/ব্যর্থ ও কেন
- পরিসর: আপাতত **শুধু Mason-এর নিজের অ্যাকাউন্টে** চালু থাকবে

### MVP-এর পরে
- এক পোস্টে একাধিক ছবি
- চাইলে Ad copy জেনারেটর দিয়ে ক্যাপশনের সাহায্য
- সবার (সব গ্রাহকের) জন্য খোলা — তার জন্য Meta App Review লাগবে (Phase 4)

### যা এই ফিচারের বাইরে
- Instagram পোস্টিং (Page-এর সাথে IG যুক্ত থাকলেও আলাদা API ও অনুমতি লাগে)
- কমেন্টের উত্তর, ইনবক্স, পোস্ট বুস্ট (বুস্ট মানেই অ্যাড — সেটা New ad-এর কাজ)
- রিলস হিসেবে আলাদা ফরম্যাটিং (সাধারণ ভিডিও পোস্টই যাবে)

## ৩. Meta Graph API — কোন কল কীভাবে

সব কল Page access token দিয়ে হবে (user token দিয়ে সরাসরি পোস্ট হয় না)। Graph version: বিদ্যমান `v23.0`।

| পোস্টের ধরন | Endpoint | মূল প্যারামিটার |
|---|---|---|
| শুধু লেখা | `POST /{page-id}/feed` | `message` |
| ছবি | `POST /{page-id}/photos` | `url` (signed URL) + `caption` |
| ভিডিও | `POST /{page-id}/videos` | `file_url` (signed URL) + `description`, চাইলে `title` |
| একাধিক ছবি (Phase 3) | প্রতি ছবি `/photos` (`published=false`) → তারপর `/feed` | `attached_media[]` |
| শিডিউল (Mason-এর সিদ্ধান্ত: Hook-এর নিজের) | পাবলিশের মুহূর্তে উপরের কলগুলোই | পোস্ট ডাটাবেসে `scheduled` থাকে; Hook-এর cron (rules cron-এর প্যাটার্নে) সময় হলে approve করা পোস্ট পাবলিশ করে। দ্রষ্টব্য: বিদ্যমান cron ঘণ্টায় চলে — শিডিউলের সময় ±১ ঘণ্টা পর্যন্ত এদিক-ওদিক হতে পারে; মিনিট-নির্ভুল চাইলে pg_cron-এর ব্যবধান কমাতে হবে |

কারিগরি নোট:
- বিদ্যমান `graphRequest` POST বডি পাঠায় `URLSearchParams` আকারে — URL-ভিত্তিক ছবি/ভিডিও পোস্টে এটাই যথেষ্ট, নতুন আপলোড পদ্ধতি লাগবে না। ভিডিওর জন্য `timeoutMs` বাড়িয়ে দেওয়া যাবে (ফাংশনে অপশন আছে)।
- Facebook signed URL থেকে ফাইল টানতে পারে কিনা — অ্যাডের ফ্লোতে (`launchRun.ts`) হুবহু এই পদ্ধতি এখন চলছে, তাই ঝুঁকি কম। কোনো ফাইলে ব্যর্থ হলে বিকল্প: `graphRequest`-এ multipart (FormData) সাপোর্ট যোগ করে সরাসরি ফাইল বাইট পাঠানো — শুধু দরকার হলেই করা হবে।
- সফল হলে Meta `id` (post/photo/video id) ফেরত দেয়; permalink পেতে `postStates`-এর মতো করে `permalink_url` পড়া হবে।

## ৪. ডাটাবেস পরিবর্তন

নতুন migration: `supabase/migrations/0039_page_posts.sql` (সর্বশেষ চলতি নম্বর 0038)

টেবিল `public.page_posts`:
- `id` uuid PK, `user_id` uuid (auth.users, cascade), `client_id` uuid null
- `page_id` text, `page_name` text
- `kind` text: `text | photo | video | multi`
- `caption` text
- `media` jsonb: `[{path, kind, name}]` — `ad-media` bucket-এর পাথ (launch-এর মতোই)
- `status` text: `draft` (অনুমোদনের অপেক্ষায়) `| approved | scheduled | publishing | published | failed`
- `approved_at` timestamptz null — কে কখন approve করল তার ছাপের জন্য `approved_by` uuid null
- `scheduled_at` timestamptz null
- `fb_post_id` text null, `permalink` text null, `error` text null
- `created_at`, `updated_at`, `published_at`

নীতি:
- RLS চালু থাকবে; `meta_connections`-এর মতো "শুধু নিজের সারি" পলিসি (select/insert/update/delete)।
- Migration সম্পূর্ণ additive — পুরনো কোনো টেবিল বা ডাটা বদলাবে না, রোলব্যাক মানে টেবিল ফেলে দেওয়া।
- Storage: নতুন bucket না বানিয়ে `ad-media` bucket-ই ব্যবহার হবে, পাথের প্রিফিক্স হবে `{user_id}/posts/...`।

## ৬. পাবলিশ ফ্লো ও নিরাপত্তা

Hook-এর বিদ্যমান নীতি (অনুমোদন ছাড়া Meta-তে লেখা নয়) এখানেও প্রযোজ্য:

1. **ড্রাফট → অনুমোদন → পাবলিশ (Mason-এর সিদ্ধান্ত):** ফর্মে তৈরি প্রতিটা পোস্ট প্রথমে `draft` থাকে। Mason তালিকা থেকে পোস্টটা দেখে **Approve** করলেই শুধু সেটা পাবলিশযোগ্য হয়। Approve না করা পোস্ট কোনোভাবেই — হাতে চালিয়েও নয়, cron দিয়েও নয় — পেজে যাবে না।
2. Approve করা পোস্টে: সময় না থাকলে "Publish now" দিয়ে তখনই, সময় থাকলে `scheduled` অবস্থায় cron সময়মতো পাবলিশ করে। শিডিউলের সময় পেরিয়ে গেলে কিন্তু approve না হয়ে থাকলে পোস্টটা `draft`-ই থাকবে ও তালিকায় "সময় পেরিয়েছে, অনুমোদন বাকি" হিসেবে দেখা যাবে।
3. পাবলিশ শুরু হলে স্ট্যাটাস আগে `publishing` করা হবে (ডাটাবেসে), তারপর Graph কল — যাতে ডাবল-ক্লিকে বা রিফ্রেশে একই পোস্ট দুবার না যায়।
4. Graph কল ব্যর্থ হলে স্ট্যাটাস `failed` + Meta-র এরর বার্তা দেখানো যাবে। **স্বয়ংক্রিয় retry হবে না** — ফলাফল অজানা থাকলে (timeout) "পেজে গিয়ে যাচাই করুন" বার্তা দেখানো হবে, কারণ পোস্টটা আসলে গিয়ে থাকতে পারে।
5. টোকেন সবসময় সার্ভারে, এনক্রিপ্টেড — ব্রাউজারে কখনো যাবে না (বিদ্যমান নীতি অনুযায়ী)।
6. Page token শুধু সার্ভার-side-এ আনা হবে, লগে ছাপা হবে না।
7. **পরিসর সীমাবদ্ধ রাখা:** ফিচারটা আপাতত শুধু Mason-এর অ্যাকাউন্টে দেখা/চলা যাবে (সার্ভার-side-এ user যাচাই করে গেট করা) — কোড সাধারণভাবেই লেখা হবে, যাতে পরে সবার জন্য খোলা সহজ হয়, কিন্তু রোলআউট শুধু একটি অ্যাকাউন্টে।

## ৭. ধাপে ধাপে বাস্তবায়ন (আনুমানিক সময়সহ)

সময়গুলো আনুমানিক ধারণা, প্রতিশ্রুতি নয়।

- **Phase 0 — প্রস্তুতি (ঘণ্টাখানেক):** লোকালে প্রজেক্ট চালানো (`.env.local` Mason-এর কাছ থেকে নিরাপদে — চ্যাটে সিক্রেট নয়), dev-এ Janata Leather পেজ দিয়ে বর্তমান সংযোগ যাচাই।
- **Phase 1 — MVP (মূল কাজ):** migration + `pagePublish.ts` + ফর্ম (আপলোড **ও** Drive লিংক দুটোই) + actions + ন্যাভ + ড্রাফট/approve ফ্লো + এখনই-পাবলিশ। ধরন: লেখা, এক ছবি, এক ভিডিও। ফিচার শুধু Mason-এর অ্যাকাউন্টে গেট করা। যাচাই: টেস্ট পেজে তিন ধরনের পোস্টই approve-এর পর টাইমলাইনে দেখা যাওয়া, আর approve ছাড়া কোনো পোস্ট না যাওয়া।
- **Phase 2 — Hook-এর নিজের শিডিউল:** cron রুট (`api/cron/page-posts`), scheduled পোস্টের তালিকা/স্ট্যাটাস পূর্ণাঙ্গ করা।
- **Phase 3 — বাড়তি:** একাধিক ছবি, চাইলে AI ক্যাপশন সাহায্য।
- **Phase 4 — সবার জন্য খোলা (আপাতত স্থগিত, Mason-এর সিদ্ধান্তে শুধু নিজের অ্যাকাউন্ট):** `pages_manage_posts`-এর Advanced Access-এর জন্য App Review: Business Verification, স্ক্রিন রেকর্ডিং, রিভিউয়ার অ্যাকাউন্ট — `docs/meta-app-review.md`-তে ads_read-এর জন্য সাজানো ধাপগুলোর সাথে মিলিয়ে। (এই ধাপ Meta-র সময়ের উপর নির্ভরশীল; কোডের কাজ নয়।)

## ৮. টেস্ট পরিকল্পনা

- **Development mode-এ পরীক্ষা:** Meta অ্যাপে Mason admin/tester, তাই App Review ছাড়াই নিজের পেজে আসল পোস্ট করে পরীক্ষা করা যাবে।
- **টেস্ট ম্যাট্রিক্স:** লেখা-শুধু / ছবি / ভিডিও × এখনই / ড্রাফট / শিডিউল; ভুল পেজ বাছাই; অনুমতি না থাকা পেজ (এরর বার্তা ঠিকমতো আসে কিনা); বড় ভিডিও; বাংলা ক্যাপশন (ইউনিকোড)।
- **যাচাইয়ের পদ্ধতি:** প্রতিটা টেস্ট পোস্টের permalink ধরে Facebook-এ খুলে দেখা; Hook-এর তালিকার স্ট্যাটাসের সাথে মিলানো।
- **বিল্ড যাচাই:** `npm run build` ও `npm run lint` পাস; বিদ্যমান পেজগুলো (dashboard, launch, manage) আগের মতো চলছে কিনা spot-check।
- **প্রোডাকশনে দেওয়া:** প্রথমে শুধু Mason-এর অ্যাকাউন্টে পরীক্ষা, তারপর সবার জন্য।

## ৯. ঝুঁকি ও সীমাবদ্ধতা (আগেই জানা ভালো)

- **App Review ছাড়া সর্বজনীন ব্যবহার যাবে না:** অ্যাপ Development mode-এ থাকায় শুধু অ্যাপের role-ধারী/Tester-রা সংযোগ দিতে পারে। Mason-এর নিজের ব্যবহারে বাধা নেই; গ্রাহকদের জন্য খুলতে Phase 4 লাগবে। `pages_manage_posts`-এর Advanced Access-এর জন্য পোস্টিং ফিচারটা আসলে ব্যবহার হচ্ছে — এমন প্রমাণ (স্ক্রিন রেকর্ডিং) Meta দেখতে চাইবে।
- **টোকেনের মেয়াদ:** দীর্ঘমেয়াদি user token ~৬০ দিনে শেষ হয়; মেয়াদ শেষ হলে পোস্ট ব্যর্থ হবে ও পুনঃসংযোগ চাইবে — এরর বার্তায় সেটা পরিষ্কার থাকতে হবে (বিদ্যমান সংযোগ ফ্লোতেই এই আচরণ আছে)।
- **আগের সংযোগীদের অনুমতি:** যারা `pages_manage_posts` যোগ হওয়ার আগে সংযোগ করেছে, তাদের Settings থেকে "Update Facebook permissions" একবার চাপতে হবে — ফিচারের পেজে অনুমতি না থাকলে সেটাই বার্তা হিসেবে দেখানো হবে।
- **ভিডিওর আকার/সময়:** signed URL পদ্ধতিতে Meta নিজে ফাইল টানে, তাই বড় ভিডিওতেও সার্ভার timeout-এর ঝুঁকি কম; তবু চরম বড় ফাইলে Meta-র নিজের সীমা প্রযোজ্য।
- **Page-এর ভূমিকা:** যে Facebook প্রোফাইল দিয়ে সংযোগ, তার ওই পেজে পোস্ট করার ক্ষমতা (full control / task access) থাকতে হবে; না থাকলে Meta এরর দেবে, Hook সেটা বার্তা আকারে দেখাবে।

## ১০. Mason-এর সিদ্ধান্ত (2026-11-03 — সব ঠিক হয়ে গেছে)

1. **শিডিউলের পদ্ধতি:** Hook-এর নিজের সিস্টেম — পোস্ট Hook-এ শিডিউল হবে, Hook-এর cron সময়মতো পাবলিশ করবে। (Meta-র native scheduled post নয়।)
2. **মিডিয়ার উৎস:** দুটোই — সরাসরি আপলোড **এবং** Google Drive লিংক, প্রথম সংস্করণ থেকেই।
3. **কোন পেজে পোস্ট যাবে:** পেজের **তালিকা থাকবে, সেখান থেকে select** করতে হবে।
4. **ড্রাফট/অনুমোদন:** সব পোস্ট **ড্রাফটে থাকবে; Mason নিজে approve করে দেবেন** — approve ছাড়া পাবলিশ হবে না।
5. **পরিসর:** আপাতত **শুধু Mason-এর নিজের অ্যাকাউন্টে** থাকবে।
